# Known issues and divergences

Each entry gives the difference from Pandoc 3.13, its reason and its state.

## Deliberate divergences

| ID | Difference | Reason |
| --- | --- | --- |
| D-001 | `--version` prints a second line that names Randoc and its version. | Required by the project goal. The first line is equal to the Pandoc line, so tools that check the version keep working. |
| D-002 | Randoc stops at a nesting limit (`Limits::max_nesting_depth`). Pandoc has no limit. | Input is not trusted. The limit of the program is 16384 levels. The JSON reader counts JSON levels: it accepts 32768 nested arrays and objects, so the document depth that it accepts depends on the node type (for example about 16000 nested block quotes or 10900 nested divs). The JSON parser stops at the first array or object over the limit with `JSON parse error: the document is nested too deeply`, so it does not report a syntax error after that point. The library functions `json::from_json` and `json::value_from_json` use a limit of 1024 JSON levels; `json::from_json_with_limit` takes the limit from the caller. |
| D-003 | The types of the document model use the derived `Clone`, `PartialEq` and `Drop`, which recurse. In a debug build on a 2 MB stack, `clone` of nested table cells overflows the stack between 200 and 400 levels, and `clone` of nested block quotes between 800 and 1600 levels. | A manual `Drop` for a node type forbids moving a field out of a node, which readers and writers do. The crate documentation of `randoc-ast` states the precondition: 200 nested tables or 510 nested levels of the other containers are safe on a 2 MB stack (test `a_tree_at_the_documented_depth_is_safe_on_a_small_stack`); the JSON reader accepts at most 510 nested block quotes and 127 nested tables by default. Readers stop at `Limits::max_nesting_depth` (128 by default), and the program uses a 1 GiB stack for its limit of 16384. Found by both reviews of json-codec, round 2 (Opus R2-01, Codex JC2-01). |

## Open divergences

| ID | Area | Difference | State |
| --- | --- | --- | --- |
| I-001 | JSON reader | The text of a JSON error was different. | Closed by the workstream json-codec: the reader gives the path and the text of `aeson` for each error class (551 cases in 8 files of `conformance/cases/json/`, 540 of them new). The remaining difference is I-JSON-01. |
| I-002 | Program | Only `-f`, `-t`, `-o`, `--version` and input files work. The formats on `main` are `json` and `native`. | Open. The command-line workstream replaces the first version. |
| I-CORPUS-01 | Corpus | Randoc fails each unit of the document corpus (`spec/corpus.json`). The corpus has no `json` input, and Randoc has only the JSON reader and writer. | Open. The result changes when the format workstreams merge. See `docs/CORPUS.md`. |
| I-CORPUS-02 | Corpus (oracle) | Pandoc needs about 100 s of wall time (5 s of CPU time) to read `jupyter-running-code` (`jupyter/notebook`, `Running Code.ipynb`). The other notebooks need less than 1 s. | Kept as found. Its manifest entry sets `timeout = 300`. The default time limit stays 60 s. |
| I-LAYOUT-01 | Layout | `randoc-layout` has no port of `realLengthWideContext` (ambiguous characters as width 2). No Pandoc writer that Randoc ports needs it yet. | Open. Port it when a writer needs it. |
| I-LAYOUT-03 | Layout | `randoc-layout` does not export the `Doc` constructors or the `HasChars` class of `doclayout`. A Rust `Doc` holds `String` text only, and the constructors are internal so that the flat form of concatenation stays valid. `realLengthWideContextNoShortcut` is missing for the reason of I-LAYOUT-01. | Open. Add a function when a workstream needs one. |
| I-LAYOUT-02 | Layout | The Lua module `pandoc.layout` has no `link` function, so the OSC 8 output of `link` has no oracle test. Its tests follow the `doclayout` 0.6 source. | Open. Compare with `pandoc -t ansi` when the ansi writer exists. |
| I-LAYOUT-04 | Layout | `Doc::update_column` returns `usize`, so a column that is negative after integer overflow becomes 0. Input: `lblock(isize::MAX as usize, literal("")) + lblock(isize::MAX as usize, literal("")) + literal("c")`. Pandoc gives `update_column(d, 0)` = -1, and Randoc gives 0. `offset`, `min_offset` and `height` are equal to Pandoc (0, 0 and 1). Only widths near the largest integer can give a negative column. | Accepted. A `usize` column is simpler for writers. |
| I-LAYOUT-05 | Layout | A block of a very large width allocates the padding of its lines. Input: `rblock(usize::MAX, literal("a"))`. Pandoc returns at once, because Haskell builds the padding only when it is needed; Randoc stops with an allocation failure. The documentation of `lblock`, `rblock` and `cblock` says that the width must be a real column width. | Accepted. Writers give column widths. |
| I-NATIVE-01 | JSON form (`randoc-ast`) | An infinite `Double` is written as `null`, and `-0.0` stays negative when it is read. Pandoc writes `"+inf"` and `"-inf"`, and the JSON reader does not accept those strings. The native reader and writer are correct. | Closed by the merge of the workstream json-codec: the JSON form of special doubles is now equal to Pandoc. |
| I-NATIVE-02 | Native writer | The writer stops at `max_nesting_depth` and returns an application error (exit code 4). Pandoc has no limit. | Deliberate, as D-002. The limit of the program is 16384 levels. |
| I-NATIVE-03 | Native reader | Input deeper than 6 value levels for each permitted tree level gives `couldn't read native`. Pandoc has no limit. | Deliberate, as D-002. |
| I-NATIVE-04 | Native reader | Pandoc expands each literal tab in the input before the native reader runs (`Str "a<TAB>b"` reads as `Str "a  b"`, unless `--preserve-tabs`). The command-line workstream owns that step in input preparation, so the native reader does not handle tabs. | Open until the command-line workstream adds tab expansion. An escaped `\t` stays a tab in both programs. The units `native/read/literal-tab#read` and `native/read/literal-tab#e2e:native` fail until then. |
| I-NATIVE-05 | Native writer | The output grows with the square of the nesting depth, because each line has its indentation. For example, 3000 nested block quotes give 36,093,037 bytes. Pandoc gives the same bytes (checked at 1000 and 3000 levels), so the writer has no output limit. 10,000 nested block quotes give 400,310,037 bytes, the same bytes as Pandoc: the release build of Randoc needs 8.2 s and Pandoc needs 12.1 s on the same loaded machine. The debug build needs more than 60 s. | Not a divergence. Recorded for capacity planning. |
| I-JSON-01 | JSON reader | An integer field (`Int`) whose exponent of `aeson` wraps to an extreme value. When the exponent of the value is `i64::MIN` after the wrap, Pandoc stops with the internal error `magnitude: with negative argument` of the library `scientific` (exit code 1), for example `1e-9223372036854775808`, `1e9223372036854775808`, `10e-9223372036854775808` and `-10e-9223372036854775808`. When the exponent is near `i64::MAX` or the coefficient has a fraction, Pandoc does not stop (more than 15 s), for example `1.0e-9223372036854775808`, `1.5e-9223372036854775808`, `15e9223372036854775807`, `10e9223372036854775807`, `1.00e-9223372036854775807` and `10.5e-9223372036854775808`. For each of these forms Randoc stops at once with exit code 64 and `parsing Int failed, value is either floating or will cause over or underflow`. | Open. Units `json/numbers/int-36`, `int-42` and `int-43`. Randoc does not copy a crash or a hang of the oracle. A double field reads these forms as Pandoc does. |
| I-JSON-02 | JSON reader | An error path writes a key after a dot when its first character is a letter and the others are letters or numbers. Randoc used the Rust properties `Alphabetic` and `Numeric`, which include letter numbers (`Nl`, for example `Ⅳ`) and `Other_Alphabetic` (for example `ा` and `ⓐ`). | Closed by the workstream json-codec: Randoc uses the general categories L and N of Unicode 15.1, as the Haskell functions `isAlpha` and `isAlphaNum` of GHC do (cases `json/keys/path-*-key`). |
| I-SHARED-01 | `randoc_core::shared` | `named_entity` has the legacy names without `;` (for example `copy`). The Markdown reader of Pandoc keeps such a reference as text, so no oracle result checks their values. The replay checks only that the Markdown rule keeps them as text. | Open. Check the values with the HTML reader workstream, if that reader uses this table. |
| I-SHARED-02 | `randoc_core::shared` | `stringify_meta` gives `true` or `false` for `MetaBool`. Two oracle entrances agree: `pandoc.utils.stringify`, and a template variable (`$foo$` gives `true` with `-t plain --template`). | Closed: no divergence. Kept as a record of the rule. |
| I-SHARED-03 | `randoc_core::shared` | `default_abbreviations` can be incomplete. `tools/abbreviations.py` tests only its candidate space: 1 to 4 letters with a final period; 2 to 4 letters with one inner period and a final period; words of 2 to 8 letters of `/usr/share/dict/words` with a final period; each in lower case and with a capital first letter. An abbreviation outside this space (for example with 5 letters and an inner period, or in capital letters) is not in the set. | Open. |
| I-SHARED-04 | `randoc_core::shared` | Two Unicode versions, both measured with the oracle. The identifier classes use Unicode 15.1 (a sweep of 166109 code points in 6 modes: a letter that 16.0 added goes). `nfc` uses Unicode 18.0.0: `tools/shared_nfc.py --measure` sent 818502 probes (each code point X alone, `a X U+0323` and `a X U+0334`) for 272834 code points (planes 0 to 3 and U+E0000 to U+E0FFF complete, each 97th code point elsewhere) through `pandoc -f commonmark`. Differences from the NFC of each version: 15.1.0 142, 16.0.0 119, 17.0.0 55, 18.0.0 0. The 17.0 differences are marks that 18.0 adds (for example U+05C8, U+1ADE). | Kept as found. Run the measurement again when the oracle changes. |
| I-SHARED-05 | Markdown and CommonMark readers | A reader of Pandoc can make the identifier of a heading from the inlines of its first pass, before it resolves links. The Markdown reader does this for each reference link (`[text][ref]`, `[ref][]`, `[ref]`): `# A [text][ref] b` with a definition of `ref` gives `a-textref-b`. The `commonmark_x` reader does this only for implicit heading references: `# A [note x1][x1] b` after `# X1` gives `a-note-x1x1-b`, and `[text][ref]` gives `a-text-b`. The shared functions take the inlines that the reader gives them, so the reader must give the inlines of its first pass. | Open. For the reader workstreams. The replay data turns `implicit_header_references` off and has no reference links. |
| I-DATA-01 | Data files | `epub.css` is not included. The EPUB writer needs a new stylesheet, and its output differs from Pandoc. | Open. The licence (GPL-2.0-or-later, no exception in `COPYRIGHT`) does not permit a copy under the Randoc licence. See `docs/DATA_FILES_LICENCES.md`. |
| I-DATA-02 | Data files | The reference documents `data/docx`, `data/odt` and `data/pptx` (`reference.docx`, `reference.odt`, `reference.pptx`) are not included. Output of these writers differs from Pandoc. | Open. The licence (GPL-2.0-or-later, no exception in `COPYRIGHT`) does not permit a copy under the Randoc licence. See `docs/DATA_FILES_LICENCES.md`. |
| I-DATA-03 | Data files | The translations `data/translations/*.yaml` are not included. Localized terms (for example the word "Abstract") differ from Pandoc. | Open. The licence (GPL-2.0-or-later, no exception in `COPYRIGHT`) does not permit a copy under the Randoc licence. See `docs/DATA_FILES_LICENCES.md`. |
| I-DATA-04 | Data files | The Lua files `data/init.lua` and `data/creole.lua` are not included. | Open. The licence (GPL-2.0-or-later, no exception in `COPYRIGHT`) does not permit a copy under the Randoc licence. See `docs/DATA_FILES_LICENCES.md`. |
| I-DATA-05 | Data files | The Pandoc file `data/abbreviations` is not included. Randoc has its own list, `randoc_core::shared::default_abbreviations`, which comes from black-box tests of the oracle. The list can be incomplete (row I-SHARED-03). | Open. The licence (GPL-2.0-or-later, no exception in `COPYRIGHT`) does not permit a copy under the Randoc licence. See `docs/DATA_FILES_LICENCES.md`. |
| I-TPL-01 | Templates | The parser uses the Rust `Alphabetic` and `Alphanumeric` properties for `letter` and `alphaNum`. Haskell uses the general categories L* and L*, N*. Variable names with some combining marks (for example U+0345) differ. | Open. A general category table can replace the properties. |
| I-TPL-02 | Templates | A block pipe (`left`, `right`, `center`) uses a width of 100000 or less. Pandoc uses the full width and can allocate that many spaces. | Open. Intended limit against memory exhaustion. |
| I-TPL-03 | Templates | Template compilation fails with `CompileError::TooDeep` ("the template is nested too deeply") when directives (`if`, `elseif`, `for`, `$^$`, partials) nest more deeply than `max_nesting_depth`. Pandoc has no limit. Each `$^$` takes the rest of the template as its body, so 128 lines `$^$$x$` one after another also give `TooDeep`, where the oracle renders them; a loop in place of the recursion in `pNested` is a larger change of the parser. The check comes before each deeper call. Compilation needs about 10 KB of stack for each level in a debug build, so the default limit 128 runs on a 2 MB thread (tests `default_depth_fits_a_small_stack` and `excess_depth_gives_too_deep_on_a_small_stack`). | Open. Intended limit against stack overflow. |
| I-TPL-04 | Templates | A partial that includes itself two or more times (for example `two.txt` = `[$two()$|$two()$]`) expands exponentially up to the nesting limit of 50 partials. Randoc and the oracle both give no result: `pandoc --template=main.txt` with `main.txt` = `$two()$` did not end in 30 s. | Open. Same behaviour as Pandoc; the oracle has no limit on the number of expansions, so Randoc adds none. |

## Harness limits

| ID | Limit | State |
| --- | --- | --- |
| H-001 | The harness has no rule for output with random values. A test with the oracle on 76 writers (not `pdf`) showed: with `SOURCE_DATE_EPOCH` set, which the harness does, only two kinds of output change from run to run: the `urn:uuid` identifier of `epub`, `epub2` and `epub3`, and the `id` of each `ipynb` cell. | Open. Add a rule that replaces these two values with a fixed text before the comparison, and make `record` run the oracle two times to find output that is not stable. Do this before the first `ipynb` or EPUB writer workstream. |
| H-002 | The harness always sets `SOURCE_DATE_EPOCH`. Pandoc output can depend on the variable (for example, standalone LaTeX output gets a PDF trailer identifier when it is set). The behaviour without the variable has no units. | Open. Add a case field that removes a variable from the environment of one case. |
